# Запуск бота в AWS Free Plan

Этот вариант не требует вносить $30. AWS Free Plan рассчитан на новые аккаунты: бесплатный период заканчивается, когда пройдут 6 месяцев или закончатся кредиты — что наступит раньше. После этого аккаунт и сервер остановятся; автоматического перехода на платный план не будет. Для продолжения работы после бесплатного периода понадобится отдельно выбрать платный план. AWS обычно не требует карту при регистрации, но в отдельных случаях может запросить способ оплаты для проверки личности. Если на экране появится непонятное списание или предоплата, остановитесь и не подтверждайте её.

## 1. Создайте AWS-аккаунт

1. Откройте [AWS Free Tier](https://aws.amazon.com/free/) и нажмите **Create free account**.
2. Если предложат выбор, выберите **Free plan / Free account plan**, не **Paid plan**.
3. Не нажимайте **Upgrade** и не подключайте аккаунт к AWS Organizations: это может перевести его на платный план.
4. Сохраните логин и включите многофакторную защиту аккаунта.

AWS допускает бесплатный план только для новых клиентов. Проверяйте остаток бесплатных кредитов в AWS Billing Console. Перед концом срока скачайте важные файлы: после окончания бесплатного плана ресурсы перестанут быть доступны.

## 2. Создайте сервер EC2

В AWS Console откройте **EC2 → Instances → Launch instances** и задайте:

- имя, например `tg-video-bot`;
- Ubuntu Server 24.04 LTS, 64-bit;
- тип `t3.micro` (или другой тип, явно помеченный Free Tier/доступный Free Plan в консоли);
- диск 8 GiB, без дополнительных дисков;
- новую SSH key pair типа RSA или ED25519 и формат `.pem` — сохраните файл на своём компьютере;
- security group: разрешите только **SSH / TCP 22 / My IP**; не открывайте HTTP, HTTPS и другие порты.

Оставьте выбранный Free Plan. Не создавайте Elastic IP, балансировщики, снимки диска и другие ресурсы. Они для этого бота не нужны. Бесплатность и доступные типы проверьте прямо в AWS Console перед запуском: предложение и доступность зависят от аккаунта.

После запуска скопируйте из карточки VM её **Public IPv4 address** и имя пользователя Ubuntu (`ubuntu`). На Linux-компьютере, где лежит проект, ограничьте доступ к скачанному SSH-ключу и подключитесь:

```bash
chmod 400 ~/ЗАГРУЗКИ/ИМЯ_КЛЮЧА.pem
ssh -i ~/ЗАГРУЗКИ/ИМЯ_КЛЮЧА.pem ubuntu@ПУБЛИЧНЫЙ_IP
```

Замените `ИМЯ_КЛЮЧА.pem` и `ПУБЛИЧНЫЙ_IP` своими значениями. Если папка загрузок называется иначе, используйте её путь.

## 3. Безопасно перенесите проект

В новом окне домашнего терминала создайте архив из списка файлов и проверьте его содержимое. Команда перечисляет файлы поштучно и не захватывает `.env`, другие `.env.*`, Telegram session, `data/`, базу данных или виртуальное окружение:

```bash
cd "$HOME/Проекты/tg_bot"
rm -f /tmp/tg_video_bot.tar.gz && \
tar --create --gzip --file=/tmp/tg_video_bot.tar.gz -- \
  .env.example .gitignore README.md PLAN.md DEPLOY.md DEPLOY_AWS.md bot.sh pyproject.toml uv.lock \
  requirements.in requirements-dev.in requirements.lock requirements-dev.lock \
  deploy/bootstrap_vm.sh deploy/tg-video-reactions.service.in \
  tests/test_offline.py \
  tg_bot/__init__.py tg_bot/__main__.py tg_bot/ai.py tg_bot/config.py tg_bot/control.py \
  tg_bot/env_tools.py tg_bot/links.py tg_bot/metadata.py tg_bot/context.py \
  tg_bot/participants.py tg_bot/reply_ai.py tg_bot/runner.py tg_bot/state.py \
  tg_bot/stickers.py tg_bot/style.py tg_bot/telegram.py tg_bot/triggers.py \
  tg_bot/voice.py && \
tar --list --gzip --file=/tmp/tg_video_bot.tar.gz
```

Убедитесь, что в списке только файлы проекта и `.env.example`. Затем передайте архив:

```bash
scp -i ~/ЗАГРУЗКИ/ИМЯ_КЛЮЧА.pem /tmp/tg_video_bot.tar.gz ubuntu@ПУБЛИЧНЫЙ_IP:~/tg_video_bot.tar.gz && \
ssh -i ~/ЗАГРУЗКИ/ИМЯ_КЛЮЧА.pem ubuntu@ПУБЛИЧНЫЙ_IP \
  'mkdir -p "$HOME/tg_video_bot" && tar --extract --gzip --file="$HOME/tg_video_bot.tar.gz" -C "$HOME/tg_video_bot" && rm "$HOME/tg_video_bot.tar.gz"' && \
rm /tmp/tg_video_bot.tar.gz
```

## 4. Подготовьте бота на VM

В SSH-терминале сервера выполните сначала безопасный просмотр, затем установку:

```bash
cd ~/tg_video_bot
./deploy/bootstrap_vm.sh --dry-run
./deploy/bootstrap_vm.sh --apply
```

Скрипт установит Python, зависимости и службу Linux, создаст `.env` только если файла ещё нет и **не запустит бота**. Он запускается от обычного пользователя `ubuntu`, без `sudo` перед скриптом.

Дальше по [общей инструкции DEPLOY.md](DEPLOY.md) заполните `.env`, авторизуйте Telegram в SSH-терминале, выберите ID одной группы и проверьте `preview`, затем `run` без отправки. Номер телефона, код входа и пароль двухэтапной проверки вводите только в терминале своей SSH-сессии. Не присылайте их сюда и никому не отправляйте `.env` или файлы из `data/`.

## 5. Необязательный управляющий бот

Если нужен удалённый переключатель паузы, в Telegram откройте `@BotFather`, отправьте `/newbot` и создайте отдельного управляющего бота. Его токен вводится только в скрытый запрос терминала на сервере, от пользователя `ubuntu` в каталоге проекта:

```bash
cd ~/tg_video_bot
./bot.sh set-control-token
```

Ввод токена не отображается. Команда меняет только `CONTROL_BOT_TOKEN` в `.env`, устанавливает права `600` и никогда не печатает значение. Не вставляйте токен в SSH-команду, переписку или этот чат. После настройки запустите или перезапустите службу; откройте личный чат с управляющим ботом и отправьте `/start`. При запуске пульт обновит slash-меню Telegram; `/commands` показывает его полный список. Переключатели и статус доступны только Telegram-аккаунту пользовательской сессии основного бота; остальных управляющий бот молча игнорирует. Пауза сохраняется в SQLite после рестарта.

Если служба уже была включена, перезапустите и проверьте её:

```bash
sudo systemctl restart tg-video-reactions
sudo systemctl status tg-video-reactions
```

При пустом `CONTROL_BOT_TOKEN` эта возможность отключена, основной бот продолжает работать как раньше.

## 6. Включите постоянную отправку только после проверки

Сначала убедитесь в тестовой группе, что бот правильно формирует ответ. Только после этого включайте службу:

```bash
sudo systemctl enable --now tg-video-reactions
sudo systemctl status tg-video-reactions
```

Остановить бота и отключить автозапуск:

```bash
sudo systemctl disable --now tg-video-reactions
```

Телеграм-бот использует пользовательскую сессию Telegram. Файл сессии даёт доступ к аккаунту — не скачивайте его в публичные места и никому не отправляйте. На бесплатном плане AWS сервер работает только в пределах срока и кредитов Free Plan; бесплатно и бессрочно AWS его не обещает.
