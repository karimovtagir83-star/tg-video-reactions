# Реакции на ссылки в Telegram-группах

Бот работает от вашего Telegram-аккаунта и отвечает на каждую новую допустимую ссылку TikTok, Instagram Reels и YouTube Shorts только в выбранных группах. Он берет только название и описание ролика: видео и звук не скачивает и не анализирует. Если метаданные пусты или Gemini не дал пригодный ответ, бот отправляет только короткий вариант смеха, без слов из заголовка или описания. Явно неподходящее содержание и небезопасные ссылки пропускаются. Лички и каналы запрещены.

Для AI используется Gemini Developer API: ключ создается отдельно в [Google AI Studio](https://aistudio.google.com/apikey), OpenAI не нужен. У модели `gemini-3.1-flash-lite` сейчас есть бесплатный лимит, но доступность и квоты зависят от Google-аккаунта и проекта; при превышении запросы могут временно отклоняться. Для запросов отправляются только ограниченные title/description. На бесплатном уровне Google может использовать входы и ответы для улучшения продуктов и допускать их обработку рецензентами — не используйте бота с конфиденциальными ссылками или описаниями. См. [тарифы Gemini API](https://ai.google.dev/gemini-api/docs/pricing) и [условия Gemini API](https://ai.google.dev/gemini-api/terms).

## Локальный запуск

Нужны Python 3.13, `uv` и Deno (он требуется для части YouTube-ссылок). Из каталога проекта:

```bash
uv venv --python 3.13 .venv
uv pip sync --python .venv/bin/python requirements.lock
./bot.sh setup
```

Заполните `.env` локально: `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` получите на [my.telegram.org](https://my.telegram.org) → API development tools, `GEMINI_API_KEY` создайте в Google AI Studio. Оставьте `GEMINI_MODEL=gemini-3.1-flash-lite`, если не меняли модель. Если `.env` уже существует, добавьте эти строки вручную: `setup` не перезаписывает настройки. Секреты не отправляйте в чат и не добавляйте в Git.

Дальше запускайте команды через `./bot.sh`:

1. `./bot.sh check` проверит настройки локально, без сетевых запросов.
2. `./bot.sh login` выполнит вход в Telegram; код и пароль 2FA вводите только в терминале.
3. `./bot.sh chats` покажет группы и их числовые ID. Добавьте нужные ID через запятую в `ALLOWED_CHAT_IDS`, затем повторите `check`.
4. `./bot.sh preview --url "https://www.youtube.com/shorts/..."` проверит метаданные и подготовит черновик. При непустых метаданных и доступном ключе команда обращается к Google и может расходовать квоту Gemini.
5. `./bot.sh run` слушает новые ссылки и показывает черновики без отправки; AI-запросы для непустых метаданных также могут расходовать квоту. Только после ручной проверки включайте `./bot.sh run --send`.

`--send` отправляет один reply на каждое подходящее сообщение; повторная обработка того же Telegram-сообщения блокируется. У video-пути нет внутренних дневных и часовых лимитов на AI или отправки. При FloodWait бот ждёт указанный Telegram срок и повторяет попытку. Google или Telegram могут ограничивать запросы на своей стороне. Остановите программу сочетанием Ctrl+C. При обычном запуске компьютер должен оставаться включенным; для сервера AWS см. [DEPLOY_AWS.md](DEPLOY_AWS.md), для Google Cloud см. [DEPLOY.md](DEPLOY.md).

## Управление ботом

Можно создать отдельного бота через [@BotFather](https://t.me/BotFather): отправьте `/newbot` и следуйте его шагам. Токен вводите только в терминале проекта, не присылайте его в чат. В каталоге проекта выполните `./bot.sh set-control-token`; ввод будет скрыт, а в `.env` обновится только `CONTROL_BOT_TOKEN` с правами файла `600`. Пустая переменная отключает пульт, обычная работа группового бота остаётся прежней.

После этого запустите или перезапустите основной процесс, откройте личный чат с управляющим ботом и отправьте `/start`. Доступ разрешён только Telegram-аккаунту, из чьей пользовательской сессии работает основной бот; сообщения остальных пользователей и групп игнорируются. Команды `/talk_on` и `/talk_off` отдельно включают и выключают обычные ответы на сообщения. Команды `/links_on` и `/links_off` отдельно управляют ответами на TikTok, Reels и Shorts. После запуска они появляются в slash-меню Telegram, а `/commands` показывает полный список. `/pause` и `/resume` управляют общей паузой обоих режимов, а `/status` показывает их состояния и общую паузу. Команд `/video_on` и `/video_off` больше нет. Все переключатели сохраняются после перезапуска; `/resume` не меняет отдельные режимы, а при выключении обычного общения локальный контекст очищается. При активном systemd на AWS сначала выполните настройку токена от пользователя службы, затем перезапустите службу и проверьте её статус по [инструкции AWS](DEPLOY_AWS.md).

Ссылки с неподдерживаемым форматом, небезопасным перенаправлением, чрезмерным ответом сайта или явно неподходящим содержанием пропускаются. Сайты меняются, поэтому поддержка площадки не гарантирует получение метаданных с каждой ссылки; при временной ошибке или пустых метаданных бот отвечает только смехом. Для первого живого теста используйте одну группу: попросите другого участника отправить новую ссылку, сначала проверьте dry-run, а затем включайте `--send`.
